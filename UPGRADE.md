TEAA Extended 0.5.0-alpha.6 keeps the accepted Fleet V5 2c37a8a component and TEAA BASE 0.5.0-alpha.5 pin. Install it into a dedicated prefix using the platform instructions in README.md. For a Desk Hub over FRA, use `teaa hub start --actor local --account https://ACCOUNT-ORIGIN`; the CLI discovers the unique relay pair from the Desk enrollment and starts the bundled gateway. On Laptop, `teaa select-hub --account https://ACCOUNT-ORIGIN` discovers the same account connection. See EXTENDED-SETUP.md for the complete account and pair setup.

TEAA BASE 0.5.0-alpha.4 is a private successor candidate derived from the alpha.3 handoff. It changes only the guidance for the existing `FLEET_V5_WORKERS_REQUIRED` refusal: the refusal remains nonzero and workers-off setup remains explicit, while setup/doctor now tell ordinary TEAA users to preserve the disabled state and rerun TEAA with `--workers`. It does not enable workers by default or start any agent. This candidate has not been published or activated.

The published TEAA BASE 0.5.0-alpha.2 uses Fleet 4.0.4. TEAA BASE 0.5.0-alpha.3 uses Fleet V5 runtime component 5.0.0-alpha.13, ToolsEngine 0.2.0-alpha.4 and Knowledge 1.2.0 (accepted reliability core with the TEAA native Windows port). Fleet's component version is its inherited source identity; it does not identify this TEAA package as the frozen V5 study artifact. This alpha.3 source and package pair is prepared for launch-lead review; no package publication or live activation is performed by the build task.

Install alpha.3 into a new prefix alongside alpha.2, review the release manifest and component lock, then explicitly update your MCP host to the output of `teaa config --server-json`. Installation does not alter host MCP settings. Setup creates distinct `fleetV5-state`; it does not read, convert, copy or delete `fleetV4-state`. There is no automatic cross-generation state migration. Use a separately authorized Fleet migration procedure if a transfer is needed.

TEAA settings and the Knowledge repository remain in their existing per-user folders. Setup retains configured Knowledge repositories and ordinary settings. Earlier preview folders are not inspected, imported, moved or deleted. Removing an earlier app prefix is a separate manual choice. No provider sign-in, credentials, services, shortcuts, host registration or automatic enrollment are performed.
